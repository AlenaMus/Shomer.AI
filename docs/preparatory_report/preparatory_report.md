## רכיב 1 — נושא הפרויקט (Project Frame)

**Shomer.AI** הוא **שומר דיגיטלי** המסייע להורים לזהות סיכון בתקשורת הדיגיטלית של ילדם — בריונות מקוונת, איומים, תוכן מיני ושיח מצוקה — **בעברית**, מתוך **השיחה וההקשר** שלה (לא הודעה בודדת במנותק), ובהרצה מקומית (on-device) שמצמצמת תלות בענן בשלב הסיווג. תמיכה בתמונות היא מודאליות **משנית**.

| ממד | תיאור |
|---|---|
| **הבעיה** | הכלים בשוק מבוססי-מילות-מפתח באנגלית, **שופטים הודעה בודדת בלי הקשר** — ולכן מציפים בהתראות שווא (Alert Fatigue) ומפספסים בריונות שמתבררת רק לאורך השיחה. הורים נוטשים תוך ימים. |
| **המשתמש** | הורים לילדים בגילי ~8–17 בישראל (כ-1.5M בתי אב); משנית: יועצים חינוכיים וארגוני בטיחות ילדים. |
| **הערך** | סיווג עברי-ראשון, **מודע-הקשר**, מוסבר (Explainable) וחסכוני — שמבדיל בין משחק/בדיחה/ציטוט לבין איום אמיתי, ובכך **חותך התרעות-שווא**. |
| **מסגרת VALID** | **V**alue: כאב מוכח ל-~1.5M משפחות · **A**I-Core: הליבה היא המסווג + סוכן-ההקשר, לא קישוט · **L**earned: fine-tuning, agents, RAG, synthetic-data, cost-analysis · **I**nnovative: **שימוש בהקשר שיחתי להפחתת התרעות-שווא בעברית** — ציר שלא נחקר בעברית · **D**oable: MVP ב-10 מפגשים על חומרה אחת (RTX 5080, 16GB). |

חיבור לקורס: הנושא נבחר ונעול במפגשים 1–2; דו"ח זה הוא ההסכמה ("חוזה") על מה ייבנה, איך יימדד, ואיך ייטען.

## רכיב 2 — שאלת המחקר (מדד ברור)

המקור המלא: [`research_question.md`](research_question.md). תמצית להגשה:

### שאלה ראשית (הקשר ↔ false positives)
> **עד כמה הוספת ההקשר השיחתי (ההודעות הקודמות בשרשור) לסיווג בריונות בעברית מפחיתה את שיעור ההתרעות-שווא (false positives), לעומת סיווג ההודעה הבודדת במנותק — מבלי לפגוע ב-recall?**

הניסוח עומד בדרישת שקופית 7: **מה נמדד** (FPR + recall), **מול מה משווים** (אותו מודל ללא הקשר — context-blind), ו**מה נחשב הצלחה** (ירידת FPR מובהקת עם recall לא-נחות).

### תת-שאלת יסוד (RQ1 — טקסט)
> עד כמה מודל QLoRA fine-tuned בעברית מסווג בריונות, לעומת zero-shot prompting על אותו מודל בסיס?

### מדדים, baseline והגדרת הצלחה
- **מדד ראשי:** שיעור התרעות-שווא (**FPR**) וההפרש בינו בין שני התנאים. **מדד שמירה:** recall. **מדדי-על:** precision, macro-F1.
- **Baseline:** סיווג **context-blind** (אותו מודל, הודעה בודדת) + zero-shot ל-RQ1 + מספרי SinaLab.
- **הצלחה:** ירידה **מובהקת סטטיסטית** ב-FPR במעבר ל-context-aware, עם recall לא-נחות, מוכחת על **gold set אמיתי** וניתנת לשחזור מ-GitHub.
- **השערות:** H1 — context-aware מפחית FPR ב-≥ X נק' בלי לאבד יותר מ-Y נק' recall; H2 — עיקר ההפחתה במקרי **"היפוך-הקשר"**; H3 — QLoRA מנצח zero-shot (RQ1).

## רכיב 3 — סקירת ספרות, מאמרי דגל, baseline ופער

המקור המלא: [`literature_flagship.md`](literature_flagship.md) (ציטוטים מאומתים) + [`references.bib`](references.bib).

### עוגנים — כל אחד מחזיק ציר אחר
1. **דאטה+משימה (עברית) — SinaLab Offensive-Hebrew (Hamad et al., 2023):** סכמת התוויות + baseline טקסטואלי מבודד = **בדיוק התנאי context-blind** שמולו השאלה משווה.
2. **הקשר — Pavlopoulos et al. (2020), ACL, "Does Context Really Matter?":** העוגן האינטלקטואלי של ציר ההקשר. הראו ששרשור-הקשר נאיבי נותן שיפור שולי — בעיה פתוחה שאנו בודקים מחדש בעברית, במיקוד FPR.
3. **התרעות-שווא — Sap et al. (2019) + Davidson et al. (2019):** classifiers חסרי-הקשר מתייגים בטעות עד ~50% מטקסט תמים. זה הכשל שהשאלה מכוונת אליו.
4. **נתונים סינתטיים — SynBullying (2025), ToxiGen (ACL 2022), "Synthetic vs. Gold" (2025):** מתודולוגיית סינתזת שיחות מתויגות (אין דאטה עברי שיחתי).
5. **מתודולוגיה — QLoRA (Dettmers et al., NeurIPS 2023):** fine-tune יעיל-פרמטרים על חומרה אחת.

### Baseline
- **context-blind:** אותו מודל על ההודעה הבודדת בלבד.  **יסוד:** zero-shot + מספרי SinaLab.

### הפער שהפרויקט סוגר (התרומה)
**אין מאמר עברי על הקשר שיחתי או בריונות תלוית-הקשר, ואין דאטהסט עברי של שיחות.** כל עבודות ההקשר/FP הן באנגלית. הפרויקט מעביר תובנה מוכחת באנגלית אל עברית, שבה טרם נבדקה — תרומה לגיטימית, לא חזרה.

## רכיב 4 — ארכיטקטורה ראשונית (Tentative — תוקפא במפגש 4)

> **שתי הכרעות נשארות פתוחות במכוון** ([`plan-structure.decision.md`](../plan-docs/decisions/plan-structure.decision.md)). הצגתן כפתוחות במפגש 3 = נקודה לאישור מול המרצה (שאלה פתוחה #1).

### זרימת המערכת (מה שכבר רץ end-to-end ב-POC)
```
[Android (Kotlin/Compose)] --HTTP--> [FastAPI :8000] --HTTP--> [Ollama :11434] -> מודל מקומי
                                          │
                                          ├── מסווג חזית: הודעה → {label, confidence}
                                          ├── סוכן הקשר: מקרה-גבול + תורים קודמים → {real_threat?, הסבר}
                                          └── (משני) image router: ocr_only / vision_only / pipeline
```
- ה-POC (Step 0) הוכיח את הצינור: אפליקציית אנדרואיד קוראת לשרת מקומי ומקבלת סיווג עברי חזרה (אומת על אמולטור + Huawei P20 Pro — PASS).
- **SDK משותף** (`server/sdk/`) יעלה ממעמד placeholder ל-SDK אמיתי עד מפגש 5 — דרישת קורס.

### 4ב — שילובי מקורות-מידע לאימון המודל על בריונות

הבעיה: **אין דאטהסט עברי של שיחות בריונות.** לכן משלבים מקורות, כל אחד לתפקיד אחר:

| מקור | מה זה | תפקיד באימון | מגבלה |
|---|---|---|---|
| **SinaLab Offensive-Hebrew** | ~15.9K ציוצים עבריים מתויגים (5 מחלקות) | בסיס המסווג הטקסטואלי + הסכמה | הודעות **בודדות**, ללא הקשר שיחתי |
| **נתונים סינתטיים-שיחתיים** | שיחות עברית רב-תוריות שנוצרו ב-LLM, **עם מקרי היפוך-הקשר מכוונים** | **ליבת האימון** לציר ההקשר | התוויות = של המחולל; פער מסלנג אמיתי |
| **תרגום+עריכה מאנגלית** | דאטהסטים שיחתיים אנגליים (SynBullying ועוד) מתורגמים + post-edit אנושי | **augmentation** — מבנה שיחה אמיתי | תרגום הורס סלנג/code-switching; תוספת בלבד |
| **gold set אמיתי בעברית** | ~100–200 קטעי שיחה אמיתיים, תיוג ידני | **הערכה בלבד** | קטן; שיקולי אתיקה |
| **לקסיקון סלנג עברי** | מילון עגה/סלנג פוגעני עכשווי | RAG לסוכן-ההקשר (לא אימון ישיר) | תחזוקה שוטפת |

**השילובים (איך הם מתחברים):**
1. **בסיס:** SinaLab (אמיתי, מבודד) → אימון מסווג החזית.
2. **שכבת הקשר:** סינתטי (עיקרי) **+** תרגום-עריכה (תוספת) → לימוד התנהגות *context-aware*.
3. **הערכה:** **gold set אמיתי בלבד** — העיקרון הוא **train-on-synthetic / evaluate-on-real** (אחרת המודל רק "מחקה את המחולל").
4. **ידע חי:** לקסיקון סלנג → RAG בסוכן-ההקשר, מתעדכן בלי אימון מחדש.

⚠️ **מלכודת לתעד בהגנה:** לא להשתמש באותה משפחת-מודל גם לייצור הדאטה וגם כבסיס המסווג — "אופים" פנימה אותן נקודות-עיוורון. ייצור במודל אחד, אימון/הערכה על אחר.

### 4ג — שתי ההכרעות הפתוחות (יוכרעו במפגש 4)
| הכרעה | אופציה A | אופציה B | יוכרע |
|---|---|---|---|
| **מודל בסיס** | Qwen2.5-7B (רץ ב-POC) / generative + QLoRA | DictaBERT (encoder) / DictaLM 2.0 | מפגש 4 |

### רכיבים ניתנים-להסבר (role/input/output/metric/fallback)
1. **מסווג חזית** — קלט: הודעה; פלט: `{label, confidence}`; מדד: macro-F1; fallback: zero-shot.
2. **סוכן הקשר** — קלט: מקרה-גבול + k תורים קודמים; פלט: `{is_real_threat, explanation, action}`; מדד: **הפחתת FPR** בלי פגיעה ב-recall; fallback: התראה גולמית.
3. **(משני) Image track** — קלט: תמונה; פלט: label; מדד: macro-F1; fallback: `vision_only`.

- **GitHub הוא יומן העבודה** — כל צעד נחתם ב-commit מתויג (`v0.1`, `v0.2`, …). מדיניות "clean run": כל צעד רץ מ-clone טרי.
- **ראיות קיימות:** היסטוריית הריפו המאוחד; תוצרי ה-POC (`integration/results/integration-1/` — אמולטור + P20 Pro, PASS); לוגי audit (`server/logs/`).
- **decision log** — כל בחירה אמיתית → `plan-docs/decisions/` (כולל reframe שאלת המחקר). **prompt book** — [`prompt-book.md`](prompt-book.md).
- **פעולה למפגש 3:** commit של כל מסמכי המפגש + עדכון README + tag (יעד `v0.2`/`v0.3`).

## רכיב 7 — סוכני AI (חוק הזהב — חובה)

סוכני AI הם רכיב **פונקציונלי** עם תפקיד, גבולות אחריות ומדדי הצלחה — לא קישוט. שני נתיבים:

### Path A — סוכן בפיתוח (חובה, פעיל כבר עכשיו)
**Claude Code** משמש כסוכן פיתוח: ניסוח שאלת המחקר, הרכבת דו"ח זה, כתיבת התכנית העסקית, אימות ציטוטים, ארגון התכנון. מתועד ב-[`prompt-book.md`](prompt-book.md) בפורמט 7 שדות (Goal · Context · Prompt · Model · Output · Evaluation · Decision).

### Path B — סוכן במוצר (עכשיו במרכז התזה; יוכרע במפגש 4)
**סוכן ההקשר הוא כעת לב התרומה** — הוא המנגנון שמפחית false positives (השאלה הראשית). יוגדר כסוכן AI אמיתי: tools (`search_conversation_history`, `check_user_age`, `lookup_slang`, `is_game_context`), memory, ו-stop-conditions. כך נוצר product-agent שניתן למדוד (ΔFPR) ולהדגים בהגנה. אם תיבחר ארכיטקטורת שרת-יחיד — חובה להסביר כיצד הלוגיקה מודעת-ההקשר מתממשת בלעדיו.
