## 1 · MoSCoW — תיוג פיצ'רים

**מה השאלה:** לחלק את 15 הפיצ'רים הפוטנציאליים ל-Must / Should / Could / Won't, כדי להגדיר את גודל ה-MVP.

**ברירת מחדל לבנייה** (נקבע ב-Phase 0.5 וניתן לשנות):
- **Must:** סיווג טקסט (F1), Chat-OCR (F2), Context Agent (F3), Push notification עם הסבר (F4), Audit logging (F5)
- **Should:** דשבורד הורה בסיסי (F6), פרופיל גיל לילד (F7)
- **Could:** RAG מעל לקסיקון סלנג (F8), Statistics (F9), Help resources (F10)
- **Won't (MVP):** Multi-child (F11), Privacy UI (F12), iOS (F13), English UI (F14), Multi-device sync (F15)

**סיכון אם נשאיר ברירת מחדל:** בנייה תחל עם הנחה שהדשבורד הוא "Should" — אם ייצא שהוא בעצם "Must" להגנה, יישאר זמן.
**יעד הכרעה:** סשן ייעודי תוך 3–5 ימים מאישור ה-PRD.

## 2 · סף ביטחון להפעלת Context Agent

**מה השאלה:** מה ה-confidence range של ה-frontline שמפעיל את ה-Context Agent? קובע כמה מקרים מגיעים ל-LLM החיצוני → קובע את העלות בפועל ואת ה-recall של ה-FP-reduction.

**ברירת מחדל לבנייה:** **borderline zone = [0.3, 0.7]**, כלומר ~15% מהתעבורה ל-LLM (ראה תכנית עסקית §6).

**רציונל:**
- **תחתון 0.3:** מתחת לזה — המסווג בטוח שזה תמים → לא משלמים LLM.
- **עליון 0.7:** מעל זה — המסווג בטוח שזה בעייתי → התראה ישירה.
- **בין 0.3 ל-0.7:** הצלת ה-FP אפשרית — שווה לשלם LLM כדי להחליט.

**סיכון:** ברירת המחדל אולי שמרנית (יותר מדי קריאות LLM) או אגרסיבית (פספסנו FP-rescue אפשרי).
**יעד הכרעה:** מפגש 8 — מודדים על gold set את עקומת FPR/recall כפונקציה של רוחב ה-borderline zone; מכריעים מבוסס-דאטה.

## 3 · פורמט ההתראה להורה

**מה השאלה:** מה ההורה רואה כשמופעלת התראה? מהי אנטומיית ההודעה?

**ברירת מחדל לבנייה** (push notification בסיסי):
```
🔔 Shomer.AI · התראה
{קטגוריה}: {שם הילד} קיבל/שלח הודעה הדורשת תשומת לב
💬 "{ציטוט מקוצר עד 80 תווים}"
🧠 מדוע: {הסבר 1-משפט מה-Context Agent}
פתח דשבורד →
```

**שאלות פתוחות:**
- האם להראות את הציטוט המלא או רק תמצית? (פרטיות הילד מול ערך להורה)
- חיתוך תמונות במלואן (לצילומי מסך) או רק הטקסט שחולץ?
- כמה התראות ביום מקסימום (cap)?
- מה ההתראות עבור ה-fallback ("needs human review") — שונות בויזואל?

**יעד הכרעה:** סשן UX לפני מפגש 7 (כי מפגש 7 בונה את הסוכן ההקשר + נתיב ההתראה).

## 4 · שמירת היסטוריית שיחות

**מה השאלה:** האם המערכת שומרת היסטוריית שיחות? לכמה זמן? איך נמחק?

**ברירת מחדל לבנייה (אגרסיבית מבחינת פרטיות):**
- שמירה: **7 ימים** בלבד (rolling window) ב-SQLite מקומי
- מחיקה: cron יומי
- ללא UI למחיקה ידנית ב-MVP
- ללא ייצוא/RTBF (Right To Be Forgotten) ב-MVP

**רציונל:** 7 ימים מספיק ל-Context Agent לקרוא היסטוריה (n=5 תורים אחורה). יותר ארוך = יותר חשיפה לפריצה/דליפה.

**סיכון:** ייתכן שהורים ירצו לראות "מה קרה לפני שבועיים" — נצטרך להגן על המגבלה.
**יעד הכרעה:** לפני מפגש 5 (כי מפגש 5 בונה את ה-DB schema).

## 5 · תרחיש offline

**מה השאלה:** מה עובד כשאין אינטרנט?

**ברירת מחדל לבנייה:**
- **עובד מקומית:** סיווג חזית (DictaBERT), OCR (Tesseract), audit log
- **לא עובד:** Context Agent (LLM חיצוני)
- **התנהגות:** סיווג חזית בלבד; אם מקרה גבול → push התראה "צריכה בדיקה ידנית — אין הקשר עכשיו"
- אין offline queueing של התראות (נשלחות מיד דרך FCM אם יש חיבור לרשת)

**שאלות פתוחות:**
- האם להוסיף offline queue להתראות שיישלחו כשחוזר אינטרנט?
- האם להציע "downgrade mode" שמשתמש ב-LLM מקומי קטן (DistilBERT) כשאין ענן?

**יעד הכרעה:** סשן NFR לפני מפגש 7 (יחד עם latency budgets).

## 6 · Single-child / Family account

**מה השאלה:** האם הורה אחד מנהל ילד אחד או כמה?

**ברירת מחדל לבנייה:**
- **MVP:** Single child per account. (מודל נתונים: `parent_id` 1:1 `child_id`.)
- **Future:** Multi-child — דורש רק שינוי key ב-DB (`parent_id` → `child_id[]`).

**סיכון:** ההצעה לקוח-יעד היא "הורים לילדים 6–16" — רוב המשפחות הישראליות עם ילדים בטווח הזה יש להן יותר מילד אחד. הצמצום הזה ייראה תמוה בהגנה אלא אם תקדם דרך תשובה: *"מתועד כ-Phase 9 — חצי יום עבודה כשנגיע לפי שזה מה שצריך"*.

**יעד הכרעה:** לפני מפגש 5.

## 7 · Quiet hours / זמני שקט

**מה השאלה:** האם להורה יש שליטה מתי הוא מקבל התראות? (לדוגמה: לא בלילה, לא בעבודה)

**ברירת מחדל לבנייה:**
- **MVP:** אין quiet hours. כל התראה נשלחת מיד.
- **רציונל:** התראת בריונות היא time-critical — אם דחיתי אותה ל-8 בבוקר, החוויה הרגשית של הילד כבר התרחשה.

**שאלות פתוחות:**
- האם להוסיף "תקציר ערב" של התראות לא-קריטיות (ירוקות) במקום הצפה לאורך היום?
- האם להבחין בין רמות חומרה (אדום = מיד, צהוב = תקציר)?

**יעד הכרעה:** סשן UX לפני מפגש 7.
