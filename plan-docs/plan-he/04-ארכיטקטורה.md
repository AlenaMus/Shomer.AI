## דרישות ד"ר סגל למפגש זה

- **PRD מלא:** vision, personas, features (MoSCoW), non-functional reqs, KPIs, out-of-scope.
- **דיאגרמת ארכיטקטורה:** User → SDK → API → (model/agents) → data.
- **תכנון סוכנים — חובה:** לכל סוכן: tools, boundaries, prompts, memory, permissions, stop conditions.
- **"חוזה עבודה מאושר"** — preparatory report ממוקד סגל, מאושר לפני כניסה לבנייה.
- **PRD לכל אלגוריתם מרכזי:** כלל 1: אין קוד לפני החוזה; כלל 2: כל סוכן מתועד; כלל 3: הכל testable עם baseline + תוצאות.

## פערים ודגשים — פגישה הכי קריטית לסינכרון

**פגישה זו חייבת להבטיח את מנדט הסוכנים:**

- **Path A — חובה:** Claude Code משמש כסוכן פיתוח לאורך כל הפרויקט. לתעד: role, boundaries, prompt book entries, success metrics (accuracy/latency/token cost/quality), reproducibility.
- **Path B — מומלץ בחום:** context/alert step יוגדר כ-AI Agent (לא רק function) עם tools, memory, stop conditions. זה מייצר product agent שניתן להדגים בהגנה.
- **SDK — לסגור כ-mandatory:** `server/sdk/` עולה ממעמד placeholder ל-real SDK core — validation, business logic, error handling, observability — עד meeting 5.
- **אם בוחרים single-server ללא agents:** חייב להסביר בהגנה איך Path A מכסה את מנדט הסוכנים (Claude Code documented in prompt book).
- **Component PRDs:** classifier (input/output/metrics/risks/tests), image router (4 strategies), context/alert (אם agent).
