## מטרה

להפוך את ה-repo מ-POC לשלד מוצר: SDK פועל כשכבת כניסה יחידה, מבנה תיקיות תקני, ו-fine-tune ראשוני של המסווג העברי. בסוף הפגישה: Android app מקבל תגובה ממודל **אמיתי** — לא stand-in.

---

## דרישות ד"ר סגל למפגש זה

- **SDK — חובה:** single-entry core שדרכו עוברים כל GUI/CLI/API. מכיל: validation, business logic, error handling, observability. שום client לא מדלג עליו.
- **GitHub live:** repo structure, branches/commits/README תקניים. Clone → install → run → inspect results.
- **Code quality gate:** modularity, OOP, Ruff linting, pytest + edge cases, docstrings, secrets ב-`.env`.
- **Prompt book:** לרשום כל prompt משמעותי בפיתוח (כולל Claude Code שכתב קוד, prompt להנחיית Unsloth, וכו').

---

## איך Shomer.AI עונה על הדרישה

- **ריפו קיים:** git history ממיגרציה, Android + FastAPI + training בתיקיה אחת.
- **Fine-tune:** `training/` — scripts קיימים אך **לא הורצו** (דורש WSL2 + CUDA). `05-finetune-classifier` מגדיר: data pipeline, training script + MLflow, evaluation notebook.
- **Server/app:** `GET /health`, `POST /classify`, `POST /classify-image` — תשתית קיימת.

---

## פערים ודגשים

- **SDK — פגישה זו היא הגבול:** `server/sdk/` הוא placeholder. הפגישה מחייבת SDK אמיתי:
  - `sdk/client.py` — typed interface (`classify_text`, `classify_image`, `health`).
  - validation (Pydantic), error handling, observability (logging/tracing).
  - Android client ו-כל client עתידי עובר דרך ה-SDK, לא HTTP ישיר.
  - להחליט: SDK ב-Python (server-side) + Kotlin wrapper (Android), או generated-from-OpenAPI.
- **Stale venv:** לפני כל פיתוח — `python -m venv .venv ; pip install -r requirements.txt` מנתיב חדש.
- **training בWSL2:** Unsloth, bitsandbytes, llama.cpp — הרצה ראשונה ב-WSL2 `/mnt/c/AIDevelopmentCourse/Shomer.AI/training/`.
- **מבנה תיקיות סגל:** `src/` (agents/, services/), `docs/`, `tests/`, `config/`, `notebooks/`, `results/`, `assets/`.
