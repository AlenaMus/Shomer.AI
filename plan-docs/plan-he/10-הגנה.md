## מטרה

להגן על Shomer.AI באופן מקצועי: Narrative, Live Demo, ראיות מ-GitHub, Q&A — ולהגיש פורטפוליו שניתן להראות למעסיקים.

---

## דרישות ד"ר סגל למפגש זה

- **מבנה הגנה:** פתיחה 60 שניות / demo 3–5 דקות / ראיות 2 דקות / Q&A.
- **Live Demo:** עובד, מוכן מראש. warm up לפני הכניסה לחדר.
- **ראיות מ-GitHub:** כל טענה בשקופית — גיבוי בקובץ/commit/גרף ב-GitHub.
- **Q&A prep:** 20 שאלות צפויות עם תשובות מובנות.
- **Backup plans — 3 רמות:** (1) live demo, (2) recorded backup, (3) screenshots.
- **Submission checklist:** README, demo, video, deck, report, prompt book, code, tests, metrics.
- **Release:** `git tag v1.0-final` + GitHub Release + שליחת report + video + repo URL.
- **חיבור לקורס — ≥ 3 נושאים:** להסביר איך הפרויקט יישם נושאי קורס בהגנה.

- **Timeline הגנה:** פתיחה (60s) — "הורים לא יודעים מה הילד מקבל בעברית; Shomer.AI יודע." Demo (4 דקות) — Android app live, Hebrew text + image classification. ראיות (2 דקות) — GitHub: metrics.json, 4 גרפים, prompt book. Q&A.
- **GitHub כ-logbook:** כפי שמופיע ב-`Plan.md` — "every step ends in a tagged commit."
- **`10-defense-and-submission`** מגדיר Q&A prep, clean run, submission checklist.
- **≥ 3 נושאי קורס:** Agents (Path A — Claude Code + Path B — context/alert), Fine-Tuning (QLoRA), Multimodal AI, Token Economics.

## פערים ודגשים

- **Clean run — חובה:** `git clone` על מכונה נקייה, follow README, no manual intervention. אם נכשל — לתקן לפני יום ההגנה.
- **Power + hotspot backup:** לא לסמוך רק על Wi-Fi בכיתה — hotspot מטלפון כ-fallback לאינטרנט.
- **"אשבור לך תראש" — live demo:** להשתמש ב-test inputs שכבר הוכחו ב-integration-1 (מ-POC).
- **שאלה לא ידועה:** "שאלה מצוינת — מחוץ לסקופ עם הזמן שהיה לי, אבל הגישה שלי הייתה..." — גישה אנליטית, לא התחמקות.
- **Server URL על הטלפון:** אם מדגים עם Huawei P20 Pro — IP של PC ב-LAN; אם אמולטור — `http://10.0.2.2:8000/`.
