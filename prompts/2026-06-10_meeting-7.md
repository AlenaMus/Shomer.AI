### 4. Harm-context reframe — "alarm on harmful situations, not every offensive message" + larger set

**Prompt (restated):** Run on more context-clear inputs and a larger dataset. Do we really want an alarm on
each offensive message? It should be part of the full harmful context. (Chose "full reframe".)

**Delivered:**
- **Reframe adopted** (decision D-CFP-9): target = `alert_worthy` (harmful situation) vs `offensive_content`
  (surface). DictaBERT = content detector; Context-Agent = harm adjudicator (broadened prompt
  *is_real_threat* → *is this harmful in context*; explicitly NOT-alert on banter/one-off/sarcasm).
- **Larger generated set** `data/gold/context_harm_v2.jsonl` (`scripts/gen_harm_context.py`): **143
  multi-turn** Hebrew conversations across 13 cells, labels by generation design (limits generator≈judge
  circularity). 84 alert-worthy / 59 not.
- **`scripts/eval_harm_context.py`** (broadened harm judge, scores vs alert_worthy + old offensive target) +
  **`scripts/viz_harm_context.py`** → `docs/research_question/plots_harm/` (4 annotated figures).
- **Result:** offensive-but-NOT-harmful **0 alerts / 100% correct** (reframe validated — no alarm on every
  offensive word); veiled-harmful recall **0→100%** with context; overall harm-recall **58→83% (+25pp)**;
  **0 false alarms on truly-benign chat**. The only residual "false alarms" = children **disclosing abuse**
  (`self_or_report`) — arguably correct → labelling refinement, not a failure.
- **Write-up** `docs/research_question/harm_context_results.md` — ties to the per-message MVP: context **cuts
  false positives** (D-CFP-8) AND is **required for harm recall** (this). Combined claim: alert on the harmful
  *situation*, not the offensive *word*.

**Decision:** D-CFP-9 in `context-fp-experiment.decision.md`.
